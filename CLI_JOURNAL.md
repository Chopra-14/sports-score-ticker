# CLI_JOURNAL.md

## Apache Kafka CLI Journal

This document records the Kafka CLI commands used during the development and testing of the Sports Score Ticker project.

---

# 1. Create Topics

## Command

```bash
kafka-topics.sh \
--create \
--topic match-events \
--bootstrap-server localhost:9092 \
--partitions 5 \
--replication-factor 1
```

## Output

```text
Created topic match-events.
```

## Explanation

This command creates the primary Kafka topic used for storing all sports match events generated by the producer application.

The topic was configured with:

* Partitions: 5
* Replication Factor: 1

Multiple partitions enable parallel processing and consumer scalability.

# 3. Describe Topics

## Command

```bash
kafka-topics.sh \
--describe \
--topic match-events \
--bootstrap-server localhost:9092
```

## Output

```text
Topic: match-events
PartitionCount: 5
ReplicationFactor: 1
Configs:
```

## Explanation

The describe command displays metadata about a topic.

Important information includes:

* Number of partitions
* Replication factor
* Partition leader assignments

This was used to verify the required partition count.

# 5. Consumer Group Information

## Command

```bash
kafka-consumer-groups.sh \
--bootstrap-server localhost:9092 \
--list
```

## Output

```text
sports-consumer-group
alerts-consumer-group
```

## Explanation

This command lists all consumer groups currently registered with the Kafka cluster.

Consumer groups enable horizontal scaling and fault tolerance.

---

## Command

```bash
kafka-consumer-groups.sh \
--bootstrap-server localhost:9092 \
--describe \
--group sports-consumer-group
```

## Output

```text
GROUP                  TOPIC           PARTITION
sports-consumer-group  match-events    0
sports-consumer-group  match-events    1
sports-consumer-group  match-events    2
sports-consumer-group  match-events    3
sports-consumer-group  match-events    4
```

## Explanation

This command displays partition assignments and lag metrics for a consumer group.

Consumer lag indicates how far behind the consumer is compared to the latest offsets available in Kafka.

Monitoring lag is important for ensuring near real-time processing.

These commands were essential for validating the Kafka infrastructure and ensuring correct producer-consumer communication.
